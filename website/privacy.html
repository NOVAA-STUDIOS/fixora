Privacy

Fixora is a desktop app that runs on your machine. This page describes exactly what it does with your code and data. In the beta it is bring-your-own-key (BYOK): there is no Fixora account and no Fixora server involved in analysis or AI.

Your code

Analysis and verification run locally. When you ask for an AI repair, the relevant slice of code (the target symbol and its evidence — never your whole repo) is sent directly to the AI provider you chose, using your own API key. It does not pass through any Fixora server. A secret gate scans every outbound payload and refuses to send anything containing an API key, private key, token, or other credential.

Your API key

Your provider key is stored encrypted using your operating system's keychain (DPAPI/Keychain) and is read only in the app's main process at the moment of a request. It is never written in plaintext, never shown in the interface after you save it, and never sent anywhere except the provider.

What is stored, and where

Your repair history — including the before/after code and each verification verdict — is stored in a local database on your machine (%APPDATA%/Fixora on Windows). It never leaves your device. Nothing about your code, file paths, prompts, or findings is logged or transmitted to us.

Telemetry

Telemetry is off by default. No usage data is sent in the beta. If a future version adds opt-in telemetry, it will be anonymous, event-level (e.g. "a fix was applied"), and will never include your code, file names, or repository identity — and it will remain off unless you turn it on.

Third parties

When you use AI, your chosen provider (e.g. OpenRouter and the model it routes to) receives the code slice for that request under their privacy terms. Choose a provider you trust; you can use a local model to avoid any third party entirely.
